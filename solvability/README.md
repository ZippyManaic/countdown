# How often has a Countdown numbers round no exact solution?

This directory establishes, by exhaustion with two independent implementations, exactly which of the
8,548,200 game instances (9,498 pools × 900 targets) have no exact solution, and derives the exact
probability under the game's deal. It also covers the full television rules (0–4 large numbers) and the
2010 "nasty" large cards {12, 37, 62, 87}. Results and proof sketches are in [RESULTS.md](RESULTS.md).
The `lean/` subdirectory belongs to a separate formal-proof effort and is not produced by anything here.

## Reproduce

```sh
./run_all.sh        # about 6 minutes on CPUs 0-23 (rustc, clang, python3 with numpy)
```

`run_all.sh` runs these steps; each can be run on its own.

| Step | Command | Output |
|------|---------|--------|
| Independent checker (Rust, no shared code) | `checker/reach RESULTS.tsv THREADS [LARGE_COUNTS] [LARGE_CARDS] > certs` | `data/checker*.tsv`, `data/certificates*.txt.gz` |
| Reference C solver over every instance | `csolve/run.sh main\|cats\|nasty` | `data/c_values*.bin` (uint32 per instance), `data/c_values_{cats,nasty}.txt.gz` (value and expression) |
| Three-way comparison | `scripts/compare.py [cats\|nasty]` | `data/compare*.txt` |
| Exact statistics, main game | `scripts/analyse.py` | `data/analysis.txt`, `data/misses.tsv`, `data/targets.tsv`, `data/perfect_pools.txt` |
| Exact statistics per ℓ = 0..4 | `scripts/analyse_cats.py` | `data/analysis_cats.txt`, `data/misses_cats.tsv` |
| Nasty large cards against standard | `scripts/analyse_nasty.py` | `data/analysis_nasty.txt`, `data/misses_nasty.tsv` |
| Dealer simulation and benchmark set | `scripts/empirical.py` | `data/empirical.txt` |
| Certificate re-verification | `scripts/verify_certificates.py [CERTS [MISSES]]`, `--answers`, `--c-texts VALUES POOLS MISSES` | `data/verify*.txt` |
| Every C answer is a legal expression with its reported value | `scripts/check_c_texts.py cats\|nasty` | `data/check_c_texts*.txt` |

## Files in `data/`

- `misses.tsv` (main game, pools in `countdown-table/pools.py` order), `misses_cats.tsv` (0, 3 and 4
  standard large), `misses_nasty.tsv` (1–4 nasty large; ℓ = 0 is in `misses_cats.tsv`): columns
  `pool` (sorted numbers, space separated), `miss_count`, `missed_targets` (comma separated, ascending).
- `checker*.tsv`: per pool, the largest reachable value M(p), the number of distinct reachable values, each
  missed target with its distance to the nearest reachable value (`t:d`), and the reachable targets whose
  only derivations end in a multiplication (`mul_only`).
- `certificates*.txt.gz`: a `# pool` line per pool, then `target<TAB>expression` for every reachable target,
  using a smallest subset. Expressions are fully bracketed with the larger operand first.
- `targets.tsv`: per target, primality, number of pools missing it, exact and decimal P(no exact | t), and
  the `mul_only` counts.
- `pools*.txt`: pool order used by the C solver runs; `c_values*.bin` is in that order, target-minor.

The certificates and C value files (about 260 MB) are not in the repository; rerun the checker and `csolve/run.sh` to regenerate them.

Sizes above 20 MB: `certificates.txt.gz` 42 MB, `certificates_nasty.txt.gz` 47 MB,
`c_values_nasty.txt.gz` 45 MB, `c_values_nasty.bin` 37 MB, `c_values.bin` 34 MB. Everything else is
under 16 MB. All of them can be regenerated by `run_all.sh`.

## Design of the checker

`checker/reach.rs` enumerates the pools itself (base-3 count of copies of each small number, all
large-card subsets of the right size), then for each pool and each subset mask builds the set of values
made using exactly that subset by combining every ordered pair of disjoint non-empty submasks with
+ − × ÷ under the paper's rules (Definition def:ops). It uses 64-bit checked arithmetic (values here stay
below 10^9), ordered maps (so output is deterministic), and keeps the first derivation of each value to
print certificates. It shares no code or data structures with any solver in the repository.
